# Insider Hunter 系统架构规格

## 1. 系统概述

Insider Hunter 是一个 Polymarket 大单追踪与内幕交易分析系统，通过监听 Polygon 链上交易数据，结合 AI 分析识别可疑的内幕交易行为。

### 1.1 技术栈

| 层级 | 技术选型 |
|------|----------|
| 后端框架 | FastAPI + Uvicorn |
| 数据库 | PostgreSQL 15 + SQLAlchemy 2.0 (异步) |
| 链上交互 | Web3.py |
| AI 分析 | Anthropic Claude API |
| 容器化 | Docker + Docker Compose |
| 语言 | Python 3.9+ |

## 2. 模块规格

### 2.1 数据库模块 (`src/db.py`)

**职责**: 数据库连接管理和会话工厂

**核心组件**:
- `engine`: 异步数据库引擎 (asyncpg)
- `AsyncSessionLocal`: 异步会话工厂
- `get_db()`: FastAPI 依赖注入
- `init_db()`: 初始化数据库表
- `close_db()`: 关闭连接池

**配置**:
```python
DATABASE_URL = "postgresql+asyncpg://user:pass@host:5432/db"
```

### 2.3 索引器模块 (`src/indexer/`)

#### 2.3.1 事件解码器 (`decoder.py`)

**职责**: 解析 Polygon CTF Exchange 的 OrderFilled 事件

**核心常量**:
```python
ORDER_FILLED_TOPIC = "0xd0a08e8c493f9c94f29311604c9de1f4e..."
CTF_EXCHANGE_ADDRESS = "0x4bFb41d5B3570DeFd03C39a9A4D8dE6Bd8B8982E"
```

**解码逻辑**:
- 从 `topics[1]` 提取 orderHash
- 从 `topics[2]` 提取 maker 地址
- 从 `topics[3]` 提取 taker 地址
- 从 `data` 解码: makerAssetId, takerAssetId, makerAmountFilled, takerAmountFilled, fee

#### 2.3.2 交易监听器 (`listener.py`)

**职责**: 处理链上事件并写入数据库

**核心方法**:
- `refresh_token_map()`: 刷新 token_id -> market 映射
- `process_log(log)`: 处理单条事件日志
- `determine_side_and_outcome()`: 判断交易方向和结果

#### 2.3.3 历史回填 (`backfill.py`)

**职责**: 批量获取历史链上数据

**配置参数**:
| 参数 | 默认值 | 说明 |
|------|--------|------|
| batch_size | 1 | 每批区块数 (QuickNode 免费版限制) |
| delay | 0.2s | 批次间延迟 |
| months | 6 | 回填月数 |

---

### 2.4 交易者画像模块 (`src/profiler/analyzer.py`)

**职责**: 分析交易者历史表现，计算胜率和分类

**分类规则**:
| 类型 | 条件 |
|------|------|
| smart_money | win_rate >= 0.6 且 total_trades >= 10 |
| dumb_money | win_rate <= 0.4 且 total_trades >= 10 |
| normal | 其他情况 |

**核心方法**:
- `update_trader_profile(address)`: 更新单个交易者画像
- `get_leaderboard()`: 获取胜率排行榜
- `get_trader_detail(address)`: 获取交易者详情

---

### 2.5 AI 分析模块 (`src/agent/insider.py`)

**职责**: 使用 Claude API 分析可疑内幕交易

**分析维度**:
1. 交易时机（结算前大额押注）
2. 交易者历史胜率
3. 单向押注模式
4. 价格异常波动

**Prompt 结构**:
```
分析以下 Polymarket 交易是否存在内幕交易嫌疑:
- 市场: {question}
- 交易者: {address}
- 金额: ${amount_usd}
- 方向: {side} {outcome}
- 交易者历史胜率: {win_rate}
...
```

**输出格式**:
```json
{
  "is_suspect": true/false,
  "confidence": 0.0-1.0,
  "reasoning": "分析理由..."
}
```

## 3. 数据流

### 3.1 市场同步流程

```
Polymarket API --> sync_markets() --> PostgreSQL (markets 表)
```

### 3.2 交易监听流程

```
Polygon RPC (eth_getLogs)
    │
    ▼
TradeDecoder.decode_order_filled()
    │
    ▼
TradeListener.process_log()
    │
    ├─── 写入 trades 表
    │
    └─── 标记 is_whale (amount_usd >= 1000)
```

### 3.3 内幕分析流程

```
trades (analyzed=false, is_whale=true)
    │
    ▼
InsiderAnalyzer.scan_pending_trades()
    │
    ▼
Claude API (AI 分析)
    │
    ▼
insider_alerts 表
```

## 5. 部署指南

### 5.1 本地开发

```bash
# 1. 启动数据库
docker-compose up -d

# 2. 安装依赖
pip install -r requirements.txt

# 3. 启动服务
py -m src.main serve

# 4. 同步市场
py -m src.main sync-markets

# 5. 历史回填
py -m src.main backfill 1
```

### 5.2 生产部署

建议使用:
- Gunicorn + Uvicorn workers
- PostgreSQL 主从复制
- Redis 缓存热点数据
- Nginx 反向代理
