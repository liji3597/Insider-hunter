## 一、项目概述

### 1.1 项目名称
Polymarket 政治突发事件内幕猎手 (Insider Hunter)

### 1.2 项目目标
构建一个基于 Polymarket 链上数据的分析系统，通过监控大额交易并结合 AI 分析，识别可能的内幕交易行为，为交易者提供市场情报。

### 1.3 核心价值
- 帮助交易者识别"聪明钱"动向
- 提供大单实时警报
- 通过 AI 分析交易时间与新闻时间的关系，发现疑似内幕交易

## 二、内部讨论记录

### 讨论主题：核心功能范围界定

**产品经理**：
用户最关心的是"谁在赚钱"和"有没有人提前知道消息"。我们应该优先实现：
1. 大单实时监控（用户能第一时间看到鲸鱼动作）
2. 聪明钱排行榜（胜率 > 90%，金额 > 1000U）
3. 内幕分析报告（AI 对比交易时间与新闻时间）

**架构师**：
同意产品优先级。技术上需要注意：
- 链上监听需要稳定的 RPC，建议支持多 RPC 容错
- 胜率计算需要等市场结算后才能确定，需要设计增量更新机制
- 本地 LLM 调用需要考虑响应时间，建议异步处理

**测试工程师**：
边界情况需要考虑：
- 市场未结算时如何处理胜率统计？
- 同一笔交易可能触发多个事件，需要去重
- RPC 断连后如何恢复？是否需要回填历史数据？

**用户代言人**：
用户体验方面：
- API 响应要快，大单列表应该支持分页
- 聪明钱排行榜需要支持时间范围筛选
- 内幕分析结果要有置信度评分

**最终决策**：
1. MVP 阶段聚焦：大单监控 + 聪明钱识别 + 内幕分析
2. 胜率统计暂时基于已结算市场计算
3. 使用本地 Ollama 模型进行 AI 分析，异步执行
4. 理由：符合黑客松时间限制，核心功能完整

## 三、功能需求

### 3.1 模块一：市场发现 (Market Discovery)

| 需求项 | 描述 |
|--------|------|
| M1.1 | 从 Gamma API 获取活跃的政治类市场 |
| M1.2 | 存储市场元数据（slug, condition_id, token_ids） |
| M1.3 | 支持定时刷新市场列表 |

### 3.2 模块二：链上交易监听 (Trade Listener)

| 需求项 | 描述 |
|--------|------|
| T1.1 | 监听 CTF Exchange 的 OrderFilled 事件 |
| T1.2 | 解码交易数据（价格、数量、方向、token_id） |
| T1.3 | 匹配交易到对应市场 |
| T1.4 | 计算 USD 金额并标记大单（> 10000 USD） |
| T1.5 | 持久化存储到 PostgreSQL |

### 3.3 模块三：交易者画像 (Trader Profiling)

| 需求项 | 描述 |
|--------|------|
| P1.1 | 统计地址的交易胜率（基于已结算市场） |
| P1.2 | 识别聪明钱：胜率 > 90% 且总金额 > 1000U |
| P1.3 | 识别笨蛋钱：胜率 < 30% 且交易频率高 |
| P1.4 | 生成交易者标签（套利者、趋势跟随者等） |
| P1.5 | 提供胜率排行榜 API |

### 3.4 模块四：内幕分析 Agent (Insider Analyzer)

| 需求项 | 描述 |
|--------|------|
| A1.1 | 扫描未分析的大单交易 |
| A1.2 | 调用 DeepSeek V3 模型搜索相关新闻 |
| A1.3 | 对比交易时间与新闻发布时间 |
| A1.4 | 生成内幕嫌疑评分和分析报告 |
| A1.5 | 标记并存储分析结果 |

**LLM 配置**：
- Base URL: `https://key.jese1357.xyz/v1`
- Model: `deepseekv3`

### 3.5 模块五：API 服务 (REST API)

| 需求项 | 描述 |
|--------|------|
| API1.1 | GET /api/whales/live - 实时大单列表 |
| API1.2 | GET /api/insider/alerts - 内幕嫌疑警报 |
| API1.3 | GET /api/market/{slug} - 市场详情 |
| API1.4 | GET /api/traders/leaderboard - 胜率排行榜 |
| API1.5 | GET /api/trader/{address} - 交易者画像 |
